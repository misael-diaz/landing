Development of a Computer Vision Engine from Scratch with C/C++

In this article you will know about some of the core ideas that laid the foundation to develop my computer vision engine from scratch.

Motivation

The motivation to develop a computer vision engine from scratch in C/C++ came from interacting with mentors and other participants in the CaribeTech hackathon. One of the mentors asked me to create a talk about interfacing C/C++ code from Python after he saw my game engine demos featuring Sonic The Hedgehog. (My favorite videogame character since childhood.) Of course I was glad to be given the opportunity to talk about writing performant code that can be called from Python. That was meaningful for me because during the event I noticed that there is real interest from developers to write C/C++ code themselves. Why would I object to that, for I was seeing my past self in them, for learning C/C++ was something that I have always wanted to do. So being able to teach something about C/C++ to those developers would be like teaching the things that I wanted to learn from someone back then.

Scope

I figured that writing in great detail about the implementation of the computer vision engine that I wrote would never be as accurate as actually reading the source code. In fact, I don't even want to talk about the code, what I want in this blog is just to share the core ideas that I used to build my own engine in the context that this is sort of a case study for Python developers with zero experience with C/C++. The message that I wanted to send was that you can write "average" C/C++ code and still get outstanding performance compared to what you would get if you have written the code in pure Python.

That's the reason why I did not research about Computer Vision algorithms to write my own. Part of the reason of doing that is to find out if I could come up with an algorithm that does the job and still performs well. And by performance I meant tracking a videogame character (in case Sonic The Hedgehog) at target rate of 30 FPS while playing the game real-time. At 30 FPS the player tracking would look great because the first installment of the game was released for the Sega Genesis console and you probably know that it's a pixel art game. Just going to say that the engine can clock at 60 FPS but at the expense of having the CPU do more work between frames. I preferred having the CPU sleep as soon as the frame was finished to keep the CPU usage as low as possible. The engine is not just performant but energy efficient in some sense.
