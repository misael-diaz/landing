Development of a Computer Vision Engine from Scratch with C/C++

In this article you will know about some of the core ideas that laid the foundation to develop my computer vision engine from scratch. And by "engine" I mean the code that provides the core functionality to my handcrafted Computer Vision Application.

Motivation

The motivation to develop a computer vision engine from scratch in C/C++ came from interacting with mentors and participants in the CaribeTech hackathon. One of the mentors asked me to create a talk about interfacing C/C++ code with Python after he saw my game engine demos featuring Sonic The Hedgehog. (My favorite videogame character since childhood.) Of course I was glad to be given the opportunity to talk about writing performant code that can be called from Python. That was meaningful to me because during the event I noticed that there was real interest from developers to write C/C++ code themselves. Why would I object to that, for I was seeing my past self in them? Learning C/C++ was something that I had always wanted to do when I was a graduate student where I spent much time writing Fortran code. So being able to teach about C/C++ to those developers would be like teaching the things that I wanted to learn from a professional developer back then.

Scope

I figured that writing in great detail about the implementation of the computer vision engine that I wrote for the event would never be as accurate as reading its source code. In fact, I don't even want to talk about the code, what I want to do in this blog is to share the core ideas that led to me the development of the computer vision engine.

The main message that I want to convey here is that even if you write "average" C/C++ code you can still get outstanding performance compared to what you would get if you have written the code in pure Python. Of course, this is general knowledge, everyone knows that applications that compile down to machine code execute faster. However, what I want to highlight here is that no matter what you write in just pure Python it is not going to get significantly better; on the other hand, when you write C/C++ code you can affect the overall performance of the code by the way that you write it. At least knowing what pitfalls to avoid can lead you to obtain code that performs well (with respect to the performance requirements of the application or your own criteria).

Starting your journey to learn C/C++

If you are interested in learning about what pitfalls to avoid to write performant code and you don't mind doing so in a non-traditional way (not a structured course, bootcamp, etc.) I would recommend you to watch Casey Muratori's handmade hero series. Even though the series has gone into a hiatus you can still watch the episodes and query about the topics that you may be interested through the handmade hero guide page. I bet you will learn a lot and the best part is that you don't have to watch the entire series (which spans about 700 episodes) to set you off on the right track.

Just want to add that if you already know how to write code in another language such as Python you can definitely learn C/C++ to develop performant software. You already have the foundational knowledge to develop applications what you need to learn are some aspects of how computers work, some syntax rules, and getting familiar with compilers (GCC and/or clang). The best advice I can give you is to start reading and writing C/C++ code, that's the best way to learn. Most importantly, don't waste time trying to learn everything that there's is to know; instead, focus your learning to just what you need to modify pixel on the screen, parse unicode files, turn on an LED, develop a video game, etc. just write some code.

Computer Vision Algorithm

At 30 FPS the player tracking would look great because the first installment of the game was released for the Sega Genesis console and you probably know that it's a pixel art game. Just going to say that the engine can clock at 60 FPS but at the expense of having the CPU do more work between frames. I preferred having the CPU sleep as soon as the frame was finished to keep the CPU usage as low as possible. The engine is not just performant but energy efficient in some sense.
